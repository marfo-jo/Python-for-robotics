## Step 1: what Allan variance measures

Take a long run of gyro samples with the IMU perfectly still. Chop it into clusters of length τ seconds, average each cluster, and ask: **how much does one cluster's average differ from the next one's?** Do that for many τ, from one sample to a large fraction of the record.

- At **short τ**, averages are dominated by white noise. Averaging m samples of white noise reduces its spread by √m, so the curve falls with **slope -1/2** on a log-log plot. That's **angle random walk**: when you integrate white rate noise into an angle, the angle error grows like √t.
- At **long τ**, slow wandering of the bias takes over, and averaging longer stops helping. The curve flattens: the **bias instability** is the floor.
- At **even longer τ**, a random walk in the rate itself makes the curve rise with **slope +1/2** (rate random walk). You may or may not see it in a 1 to 3 hour log.

So the curve is a fingerprint of the noise: each noise type has its own slope. In signal terms, it's a time-domain cousin of the power spectral density, easier to read for slow drift.

## Step 2: the estimator (this is the spec)

Given `N` rate samples `y[0..N-1]` at sample rate `fs` (so `dt = 1/fs`), and a cluster size of `m` samples (so `τ = m/fs`):

**Cluster averages**, one starting at every sample `k` (that's what "overlapping" means):

$$\bar y_k = \frac{1}{m} \sum_{i=k}^{k+m-1} y_i \qquad k = 0, 1, \ldots, N-m$$

**Overlapping Allan variance**, comparing each average with the one `m` samples later:

$$\sigma^2(\tau) = \frac{1}{2 (N - 2m + 1)} \sum_{k=0}^{N-2m} \left(\bar y_{k+m} - \bar y_k\right)^2$$

The **Allan deviation** is its square root, σ(τ), in the same units as `y` (°/s for a gyro).

Check yourself on a tiny example before writing code. For `y = [0, 0, 1, 1, 0, 0]` and `m = 1`: the averages are just the samples, the 5 differences are `0, 1, 0, -1, 0`, the sum of squares is 2, so σ² = 2 / (2 × 5) = 0.2. Now do `m = 2` by hand (you should get σ² = 1/3). The site's tests use this example.

**Why overlapping?** A non-overlapping version (averages only at `k = 0, m, 2m, ...`) is also a valid estimator, but it uses far fewer comparisons at large τ, so the right end of your curve gets very noisy. Overlapping squeezes the most confidence out of a finite log.

**Making it fast.** A direct double loop over 1 million samples and 100 values of m is far too slow in Python. The trick: with a running sum `S` (a cumulative sum with a 0 in front), the sum of any window `y[k] + ... + y[k+m-1]` is a single subtraction of two entries of `S`. So all cluster averages for one m come from one vectorized subtraction. That's the only performance idea you need.

**Choosing τ.** A log-spaced set of cluster sizes from `m = 1` up to `m = N // 2` (about 100 values, rounded to integers, duplicates removed) gives evenly spread points on a log-log plot. Beyond `N // 2` there's no second cluster to compare with.

## `allan.py`, the Python spec

Write `host/allan.py`, numpy only (scipy is **not** installed in the course env, and you don't need it).

### `allan_deviation(rate, fs, taus=None) -> (taus_out, adev)`

- `rate`: 1-D sequence or array of rate samples. `fs`: sample rate in Hz.
- `taus`: optional sequence of requested τ values **in seconds**. Each becomes a cluster size `m = round(τ × fs)`. If `None`, use about 100 log-spaced cluster sizes from 1 to `N // 2`, as above.
- Return two numpy arrays of equal length: `taus_out`, the **actual** τ values used (`m / fs`, sorted, no duplicates; a request of 0.013 s at 100 Hz uses m = 1, so it returns 0.01), and `adev`, the overlapping Allan deviation at each.
- Raise `ValueError` if `rate` isn't 1-D, has fewer than 3 samples, `fs <= 0`, `taus` is empty, or any requested τ gives `m < 1` or `m > N // 2`.

### `loglog_slope(taus, adev) -> float`

The least-squares slope of `log10(adev)` against `log10(taus)` (a straight-line fit; `np.polyfit` with degree 1 does it). Raise `ValueError` for fewer than 2 points, mismatched lengths, or any value that is zero or negative (log of zero).

### `angle_random_walk(taus, adev) -> float`

The Allan deviation read at **τ = 1 s**, interpolated **linearly in log-log space** between the nearest points. Raise `ValueError` if 1 s is outside the range of `taus`. Units: for a rate in °/s this returns °/√s (equivalently °/s/√Hz); multiply by 60 to get **°/√h**, the unit datasheets use.

## Step 4: analyze and read the curve

Convert each gyro axis to °/s, compute the Allan deviation, and plot all three axes on one log-log figure (see bg-plot), with a reference line of slope -1/2 through the ARW point.

Reading the parameters (the IEEE Std 952 conventions):

| Parameter | Where to read it | Units to report |
|---|---|---|
| Angle random walk N | on the slope -1/2 line at τ = 1 s | °/√h (multiply °/√s by 60) |
| Bias instability B | the minimum of the curve: B = σ_min / 0.664 | °/h (multiply °/s by 3600), plus the τ of the minimum |
| Rate random walk K (if visible) | on a slope +1/2 line at τ = 3 s | °/h/√h |

**Compare with the datasheet.** The MPU-6050 datasheet gives a rate noise spectral density of **0.005 °/s/√Hz**. For white noise, that number *is* the ARW in °/√s, so it predicts N ≈ 0.005 × 60 = **0.3 °/√h**. Yours will be in that neighborhood. If it's lower at short τ, look at your DLPF setting from 1.2: the on-chip filter averages neighboring samples, which pulls the first few points below the white-noise line. That's a great sentence for your README, because it shows you understand your whole pipeline, not just the formula.

Optional extension: run the same analysis on the accelerometer axes (convert g to m/s²) to get velocity random walk in m/s/√h.

## Common beginner mistakes

- Using τ in **samples** instead of seconds. The curve's shape looks right but every number is off by a factor of `fs` or √`fs`. Test: at one sample, your value must equal the noise standard deviation.
- Returning the Allan **variance** and calling it deviation: the white-noise slope comes out -1 instead of -1/2.
- Dropping the 1/2 in the formula: every value is √2 too high.
- Reading ARW off the curve at τ = 1 s when 1 s isn't on the slope -1/2 part. Fit the -1/2 line where it applies, then evaluate it at τ = 1 s.
- Recording while the chip is still warming up: the bias drift shows up as a fake rate random walk.
- Forgetting the unit conversions (°/√s to °/√h is ×60; °/s to °/h is ×3600).

Write `allan_deviation` for **one** value of m first, as a plain loop, and check it against the hand example. Then replace the loop with the cumulative-sum trick and check that the answers are identical. Only then add the loop over many m and the input checks.

</details>

<details><summary>Hint 2 (approach)</summary>

Build the running sum with a leading zero so it has N + 1 entries. For a given m, the window sums for every start k are "running sum from m onward minus running sum up to N − m", element by element; divide by m to get all the cluster averages at once. The differences you need are between averages m positions apart, so it's another shifted subtraction. Square, take the mean, halve it, square-root it. For the default τ list, `np.logspace` then round, convert to int, and `np.unique`.

</details>

<details><summary>Hint 3 (pseudocode)</summary>

```
allan_deviation(rate, fs, taus):
    y = rate as a float array; validate (1-D, N >= 3, fs > 0)
    if taus is None: ms = unique rounded log-spaced integers from 1 to N // 2
    else: ms = unique of round(taus * fs); validate 1 <= m <= N // 2
    S = cumulative sum of y with a 0 in front           (length N + 1)
    for each m in ms:
        avg = (S[m:] - S[:-m]) / m                       (N - m + 1 cluster averages)
        d = avg[m:] - avg[:-m]                           (N - 2m + 1 differences)
        adev[m] = square root of (half the mean of d squared)
    return ms / fs, adev

angle_random_walk(taus, adev):
    check 1.0 lies within [min(taus), max(taus)]
    interpolate log10(adev) against log10(taus) at log10(1.0) = 0
    return 10 to that power
```

</details>

## Troubleshooting

| Symptom | Likely cause | Fix |
|---|---|---|
| White-noise test slope is -1 | You return variance, not deviation | Square-root at the end. |
| Values are √2 too high | Missing the 1/2 | Check the formula. |
| `taus_out` is `[1, 10, 100]` instead of `[0.01, 0.1, 1.0]` | τ in samples | Divide m by fs. |
| Very slow (minutes) | Python loops over samples | Use the cumulative-sum trick; loop only over m. |
| `MemoryError` or a long hang on 3 hours of data | Loading a 50 MB CSV with a slow method, or making a huge 2-D array | `np.loadtxt` with `usecols`, or log binary and convert once; keep everything 1-D. |
| The curve has a bump or a step at a particular τ | Something periodic in the room (a fan, the HVAC cycling) or a temperature change | Note it; check the temperature column; record again somewhere quieter. |
| Right end of the curve jumps around | Only a few clusters at large τ: expected | Don't read parameters from the last few points. |
| Recording stopped after 20 minutes | Windows went to sleep, or USB selective suspend | Change the power settings; check the counters. |
